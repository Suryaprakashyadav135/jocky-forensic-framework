# JOCKY V5.3 — Project State

## One-Line Summary

A working forensic framework that creates native tools from a custom
language, compiles them with five layers of obfuscation, executes them
file-less, and delivers findings through encrypted CDN-fronted C2 — with
~80% coverage of SIH problem statement 26148.

---

## What Works (Verified)

### 1. Custom Language

- `.jky` syntax with types (int, string, array)
- 4 built-in primitives: `read_file`, `list_dir`, `exec_cmd`, `emit`
- Lexer, parser, type checker, LLVM IR codegen
- Compiles to native x86-64 ELF binaries

### 2. Five Obfuscation Layers

| # | Technique | Verified |
|---|-----------|----------|
| 1 | Control-flow flattening (dispatcher pattern) | ✅ IR shows dispatcher blocks |
| 2 | Function name randomization (`f_<random>`) | ✅ `grep define` shows random names |
| 3 | Runtime symbol randomization (`<prefix>_<letter>`) | ✅ `nm` shows randomized symbols |
| 4 | Binary stripping (`-Wl,-s`) | ✅ `strings` returns zero JOCKY markers |
| 5 | ELF entry point mutation | ✅ `e_entry` unique per build in `0x1fXX` range |

### 3. Four Forensic Scripts (Native JOCKY)

| Script | Purpose | Verified Output |
|--------|---------|----------------|
| `proc_scan.jky` | Enumerate processes + cmdlines | 350+ processes |
| `net_scan.jky` | TCP/UDP/ARP/routing tables | Real network tables |
| `persistence_scan.jky` | Cron, systemd, SSH, profiles | Real persistence locations |
| `sys_fingerprint.jky` | Hostname, kernel, uptime | Real system identity |

Every binary: zero plaintext leaks, mutated entry point, unique symbols.

### 4. File-less Execution

- `memfd_create` + `/proc/self/fd` execution
- Binary never touches disk
- `(deleted)` inode proof in `/proc/self/fd/<fd>`
- Verified with `find / -name "jocky_payload*"` returning empty

### 5. Direct Syscalls

- Hand-assembled `syscall; ret` stub running from RWX page
- libc bypassed
- Verified: `getpid()` returns the correct PID, `write()` outputs directly

### 6. Encrypted C2

- ECDH P-256 key exchange
- HKDF-SHA256 key derivation
- AES-256-GCM authenticated encryption
- Session IDs, counter-based replay protection
- Verified: same shared secret on both sides without transmission

### 7. Real Cloudflare Deployment

- Worker: `https://jocky-cdn-front.g-surya-prakash.workers.dev`
- Tunnel: real trycloudflare endpoint
- TLS 1.3, Cloudflare cert
- Client → Cloudflare → Tunnel → local server verified end-to-end

### 8. Multi-System Management

- **Multi-namespace test:** 3 network namespaces, 3 distinct IPs
- **Distinct source IPs in server log:** `192.168.100.10/11/12`
- **Per-session ECDH keys:** unique shared secrets per session
- **Live Flask dashboard:** multi-client view, 3-second auto-refresh

### 9. Deep Forensic Analysis (Python Layer)

8 categories of system inspection:
- Process (per-PID memory maps, open FDs, environ)
- Network (raw `/proc/net/*` parsing)
- Persistence (cron, systemd, SSH, shell profiles)
- Filesystem (recent, setuid, deleted-open)
- Logs (auth, sudo, shell history)
- Memory (LKMs, RWX processes)
- Users (sessions, sudoers, SSH keys)
- IOCs (file hashing, malware string scan)

Auto risk report with weighted scoring and recommendations.

### 10. CI/CD Pipeline

- Real git hook runs 5 checks on every commit
- Validates compiled binary, not intermediate artifacts
- Blocks commits that introduce leaks or break the entry point mutation
- Verified working across two commits

## What Doesn't Work (Documented)

| Gap | Reason |
|-----|--------|
| C++ LLVM pass (`FlattenCFG.so`) | Pass body not invoked on LLVM 21 plugin ABI |
| Python obfuscation extras | llvmlite lacks block-splitting primitives |
| ptrace process hollowing | Kernel W^X blocks executing from RWX pages |
| ptrace function call injection | Kernel rejects RIP redirection on syscall-stops |
| BYOVD attack capability | Windows-only technique |
| Windows-specific techniques | Out of scope for Linux/Kali |
| ELF `.dynsym` shuffle | Attempted — see docs/ for status |
| Real WAN clients | All test clients run in namespaces on the same host |

These are documented as prototype attempts with precise technical
reasons for the failure at each boundary.
